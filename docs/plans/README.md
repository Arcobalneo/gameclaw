Write a new plan here before a large change: a new game, an engine rewrite, an
MCP or leaderboard change, or a docs restructure.

Name the file `YYYY-MM-DD-short-title.md`. State the goal, scope, assumptions,
risks, and a checklist. Update the plan if the scope changes.

When the change has shipped and the maintainer docs in `docs/` are current,
delete the plan. Do not leave shipped or obsolete plans in the tree. Game
design methodology lives in
[`../references/ai-native-game-design-rules.md`](../references/ai-native-game-design-rules.md)
and is not a plan; do not delete it.

Small changes do not need a plan.

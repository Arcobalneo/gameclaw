## 2. 玩法设计

### 2.1 玩感与流程

**玩感**：读间距、高差、风与节拍，在“更远的抛物线”和“更宽的容错”之间做技术选择；性格与颜色决定初始 build，精准落地攒灯花再养成。失败能看清是跳短、跳远、体力耗尽，还是救援时反被拖下去。

- 一局 45 关，每关从当前灯柱跳到下一根，落上第 45 根即迎来天亮并获胜。
- 开局依次 `nature:<id>`、`color:<id>`；也可用 `--content <nature>:<color>` 直接选定。
- 性格：果敢（高弹力、低控制）、沉稳（高控制）、绵韧（高耐力与黏性）。颜色提供带取舍的属性修正。
- 四项 build 属性为弹力、控制、耐力、黏性；状态同时公开当前体力、灯花、摔落次数与有效属性。
- 通关 15 / 30 关各长大一次：弹力、耐力、黏性成长并补体力；体型也带来少量重量修正，后段更远的间距不会自动失效。

### 2.2 离散动作物理

- 主动作 id：`jump:<low|mid|high>:<flat|arc|high>:<early|on|late>`，依次表示力度、角度、时机。
- 使用确定性抛物线近似：初速度由力度与弹力决定，角度决定水平 / 竖直分量，高差影响飞行时间；风、体型和相对当前风拍的时机修正落点。
- 控制影响时机误差与落地容差，黏性扩大灯柱边缘容差。结果分完美、站稳、擦边、跳短、跳远；擦边仍过关但额外耗体力，失误留在原关并记一次摔落。
- 每个列出的跳跃动作都在 `detail` 中给出预计落点、误差、结果与消耗。动作按当前推荐度排序，因此通用 `next` 是明确的当前建议，不是随机选一项。
- 体力不足的跳跃不列出；`rest` 永远可用来恢复体力并推进风拍。失败动作仍可能合法，它会返回真实物理后果而不是非法动作错误。
- 完美 / 站稳落地获得灯花；`train:<stat>` 消耗 3 灯花永久提升属性（有上限），每关没有强制训练，避免刷无成本资源。
- 关数提高街速、风修正、间距与视野；风拍只由动作推进，不读真实时间。

### 2.3 连续街图与信息支持

- `state.street` 是累积灯柱数组；每次过关在已有地图末端续建，坐标、间距与高差保留，不重置成独立卡片。
- 状态只展示当前位置起的可见街段；可见范围从 2 根逐步增至 5 根，后续目标可提前阅读。
- 45 关分为旧城慢街、风口长街、高架黎明三段； headline 持续显示关卡、体型、街速和阶段。
- `status` 公开当前目标的间距、高差、基础风、当前风拍、落地容差与数值公式提示；`events` 写入实际判定值。

### 2.4 离线“网络模式”与救援

- 不联网、不伪装真人：同性格的其他果冻只是 seed 驱动的离线同伴。成功落地后可能黏连；连续多关未遇到时有确定性保底。
- 进入 `rescue` 阶段后，主街跳跃暂时不可用，只列 `rescue:<low|mid|high>:<early|on|late>` 及确有必要的缓力动作。
- 救援公开所需进度、当前拉力和剩余拍数。力度与时机共同决定进度和拉力；拉力过高或拍数用尽则失败。
- 成功奖励灯花和下一跳的同伴护持；失败消耗体力并记摔落，可能触发有明确死因的终局。救援结束后回到同一条延伸街道。

### 2.5 结局与反支配

- 胜：`dawn`，完成第 45 关。
- 负：`fall`（摔落次数到上限）、`exhausted`（力竭且跳跃失误）、`rescue-fall`（救援失败导致最后摔落）；`aborted` 独立为中止。
- 高力度不是支配策略：耗体力更多，且可能跳过灯柱；高角度并非总优，会牺牲水平距离；固定时机在移动风拍下会失误。
- 只休息不能推进关卡，只训练要花精准落地才能获得的灯花；体型成长与后段间距同步增加，build 与技术都必须参与。
- `recap` 给出最后关卡、具体动作、预测 / 实际落点、误差、摔落与体力，并只提供本局限定的 memory 观察。

## 3. 假设与风险

- 假设：不改 gamekit 契约、共享 observer/report、现有游戏玩法或 workflow；矩阵由包目录自动发现，无需硬编码新 id。
- 假设：`--content` 的预设只减少开局选择步骤，不引入另一套规则；未知或非法难度沿用现有游戏的 normal fallback 惯例。
- 风险：27 种跳跃组合造成 token 噪声 → 非 verbose 文本只列 id / 短标签，JSON 的 detail 提供精确预测，并按推荐度排序。
- 风险：浮点跨平台细微差异 → 物理中间结果定点舍入后再比较，判定值完整写入事件；规则不读时钟、不用 `Math.random()`。
- 风险：生成不可达的灯柱 → 限制间距 / 高差包线，测试多种 build、多个 seed 与合法动作全量执行；真实试玩至少推进到第一次成长。
- 风险：动作列表与执行不一致 → `act` 直接以 `actionsOf` 为唯一准入来源；测试逐个执行每个列出动作。
- 风险：救援打断主线或造成无提示死局 → 公开剩余拍数、进度、拉力和全部合法动作，失败有独立日志 / 事件 / recap 原因。
- 历史版本说明只保留在旧 CHANGELOG 与旧计划中，不改写历史；现行发行元数据全部升到 2.7.0。
